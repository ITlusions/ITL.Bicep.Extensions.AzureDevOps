Authentication

The provider authenticates to Azure DevOps using Azure AD â€” no Personal Access Token required. Credentials are resolved automatically using the following priority chain.

1

Workload Identity Federation (AKS / Azure Pipelines)

Pod identity federated to a service principal, or an Azure Pipelines service connection with Workload Identity Federation scheme. Zero secrets â€” no certificate, no password.

2

Managed Identity (ACI Â· App Service Â· VM Â· AKS node pool)

Token fetched from the IMDS endpoint at 169.254.169.254. For a user-assigned identity, set AZURE_CLIENT_ID to the identity's client ID.

3

Azure CLI â€” az login (local development)

After az login, DefaultAzureCredential picks up the CLI session automatically. No extra configuration needed.

4

Az.Accounts module (PowerShell only)

After Connect-AzAccount, the PowerShell runtime uses Get-AzAccessToken as a final fallback. Requires Az.Accounts module installed.

Quick Start

Up and running in five steps.

1

Prerequisites

Install the required tooling and ensure your Azure identity has the correct permissions.

# Tooling
az bicep upgrade                  # Bicep â‰¥ 0.29 required

2

Choose any of the three Dockerfiles. The image must be reachable by the machine running az deployment.

docker build -f Dockerfile -t itlbicep.azurecr.io/extensions/itl-azuredevops:1.0.0 .
docker push itlbicep.azurecr.io/extensions/itl-azuredevops:1.0.0

Add bicepconfig.json

Place alongside your .bicep files. Point the ado extension at your ACR image.

  "experimentalFeaturesEnabled": { "extensibility": true },
  "extensions": {
    "ado": "br:itlbicep.azurecr.io/extensions/itl-azuredevops:1.0.0"
  }
}
4

Start the provider

The Bicep engine calls the provider client-side â€” ARM never sees ADO resources. The provider must be running on the machine that runs az deployment. In CI/CD, run it as a service container.

  itlbicep.azurecr.io/extensions/itl-azuredevops:1.0.0

# User-assigned Managed Identity
docker run --rm -e AZURE_CLIENT_ID=<mi-client-id> -p 8080:8080 \
  itlbicep.azurecr.io/extensions/itl-azuredevops:1.0.0

# Azure Pipelines â€” inject a pre-fetched ADO token (see Authentication section)
# Set AZURE_AD_TOKEN in the container env from your pipeline service connection

CI/CD Pipelines

Run the provider as a service container â€” no PAT pipeline variable needed.

Azure Pipelines

azure-pipelines.yml 
resources:
  containers:
    - container: ado_provider
      image: itlbicep.azurecr.io/extensions/itl-azuredevops:1.0.0
      ports:
        - 8080:8080

jobs:
  - job: Deploy
    services:
      ado_provider: ado_provider
    steps:
      - task: AzureCLI@2
        displayName: Deploy Bicep (inject ADO token into provider)
        env:
          BICEP_EXTENSION_ADO_BASEURI: http://localhost:8080
        inputs:
          azureSubscription: my-service-connection   # WIF service connection
          scriptType: bash
          scriptLocation: inlineScript
          inlineScript: |
            ADO_TOKEN=$(az account get-access-token \
              --resource 499b84ac-1321-427f-aa17-267ca6975798 \
              --query accessToken -o tsv)
            export AZURE_AD_TOKEN=$ADO_TOKEN

            az deployment group create \
              --resource-group my-rg \
              --template-file examples/serviceconnections.bicep \
              --parameters organization=itlusions project=my-project \
                           subscriptionId=$(SUB_ID) tenantId=$(TENANT_ID) \
                           servicePrincipalId=$(SP_ID) subscriptionName="My Sub"
